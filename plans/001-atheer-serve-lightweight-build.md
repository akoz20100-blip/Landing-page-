## Why this matters

The Atheer portfolio page (`landing-pages/atheer/`) is served on GitHub Pages at
`https://akoz20100-blip.github.io/Landing-page-/landing-pages/atheer/`. GitHub Pages serves
`index.html` for that directory URL — and the committed `index.html` is a **9,693,066-byte
(9.24MB) single HTML file** in which the hero video (1.5MB mp4), all 30+ WebP images, and 6
woff2 fonts are inlined as base64 data URIs. Base64 inflates binary ~33%, and data URIs of
already-compressed WebP/MP4 barely gzip. A mobile visitor on 4G downloads ~9MB *before first
paint* — this is the flagship page being shared with a real client over WhatsApp.

The QA evidence in `landing-pages/atheer/qa/ACCEPTANCE-CHECKLIST.md` reports Lighthouse
mobile Performance 95 / LCP 1.8s — but lines 3–4 of that file show the audit ran against
**`index.source.html`** (the 64KB build with relative asset URLs), *not* the deployed
`index.html`. The artifact that was measured is not the artifact that is deployed.

The fix: swap the roles of the two build outputs. The relative-asset build becomes the
deployed `index.html`; the data-URI standalone stays available as `standalone.html` for
offline/`file://` sharing (that was its original purpose).

## Current state (verified at 79f7788)

Both files are generated by `landing-pages/atheer/_source/build.js` from
`landing-pages/atheer/_source/template.html` (tokens like `__IMG_HERO_POSTER__`,
`__F_SANS_R__`, `__VIDEO__` are replaced per-variant):

- `build.js:64-72` builds the **relative-asset variant** and writes it to
  `landing-pages/atheer/index.source.html` (65,278 bytes). Fonts resolve to absolute
  GitHub Pages URLs (`fontBase`, line 30), video to `assets/hero.mp4`, images to
  `assets/img/<name>.webp`.
- `build.js:74-82` builds the **standalone variant** (everything a data URI) and writes it
  to `landing-pages/atheer/index.html` (9,693,066 bytes).
- `build.js:88-94` prints sizes and enforces guards: standalone ≤ 12MB, source ≤ 90KB.
- All referenced assets already exist in the repo: `landing-pages/atheer/assets/hero.mp4`
  (1.5MB) and `landing-pages/atheer/assets/img/*.webp` (~4.5MB total).
- The gallery card in root `index.html:195-211` links to `./landing-pages/atheer/` and its
  thumbnail `./landing-pages/atheer/assets/img/identity-landscape.webp` — both unaffected
  by this change.
- Root `vercel.json` currently **rewrites** `/` to `/landing-pages/atheer/index.html`:

  ```json
  {
    "cleanUrls": true,
    "rewrites": [
      { "source": "/", "destination": "/landing-pages/atheer/index.html" }
    ]
  }
  ```

  A *rewrite* keeps the browser URL at `/`, which works today only because the standalone
  has no relative asset references. After this change, relative paths like
  `assets/img/hero-poster.webp` would resolve to `/assets/img/…` (404). The rewrite must
  become a **redirect** to `/landing-pages/atheer/` so relative paths resolve.

Relevant excerpt of `build.js` (lines 64–82) as of 79f7788:

```js
let source=tpl.replace("<head>","<head>\n<!-- Reference build: external Thmanyah fonts + relative video + relative WebP images. -->");

}
standalone=standalone.split("__VIDEO__").join(dataUri(VID));
for(const [token,file] of Object.entries(images)){
  standalone=standalone.split(token).join(dataUri(IMGDIR+file));
}
fs.writeFileSync(OUTDIR+"index.html",standalone);
```

## Steps

1. **Pre-flight: confirm nothing else references `index.source.html`.**
   ```bash
   grep -rn "index.source.html" --include="*.html" --include="*.js" --include="*.json" --include="*.md" . | grep -v node_modules | grep -v "^./plans/" | grep -v "^./landing-pages/atheer/qa/"
   ```
   Expected: only hits inside `landing-pages/atheer/_source/build.js` (and possibly
   `_source/HANDOFF.md`, which is fine — it's documentation of past work). If any *served
   HTML page* links to `index.source.html`, STOP and report back.

2. **Edit `landing-pages/atheer/_source/build.js`:**
   - Line 72: `fs.writeFileSync(OUTDIR+"index.source.html",source);` →
     `fs.writeFileSync(OUTDIR+"index.html",source);`
   - Line 82: `fs.writeFileSync(OUTDIR+"index.html",standalone);` →
     `fs.writeFileSync(OUTDIR+"standalone.html",standalone);`
   - Line 64: update the injected comment to say it is the deployed build, e.g.
     `<!-- Deployed build: external Thmanyah fonts + relative video + relative WebP images. standalone.html is the offline single-file variant. -->`
   - Lines 90–94: rename variables/paths so the guards follow the files:
     `standaloneSize` reads `OUTDIR+"standalone.html"`, `sourceSize` reads
     `OUTDIR+"index.html"`; keep the 12MB guard on the standalone and the 90KB guard on
     the deployed `index.html`; update the `console.log` labels to match.

3. **Rebuild:**
   ```bash
   node landing-pages/atheer/_source/build.js
   ```
   Expected output: a line like `built. …` with standalone ≈ 9.24MB, index ≈ 64KB,
   `leftover: 0`, exit code 0.

4. **Delete the old file:**
   ```bash
   git rm landing-pages/atheer/index.source.html
   ```

5. **Replace the rewrite with a redirect in root `vercel.json`:**
   ```json
   {
     "cleanUrls": true,
     "redirects": [
       { "source": "/", "destination": "/landing-pages/atheer/", "permanent": false }
     ]
   }
   ```

6. **Smoke-test locally** (read-only server, no artifacts written):
   ```bash
   python3 -m http.server 4173 &
   curl -s -o /dev/null -w "%{http_code} %{size_download}\n" http://127.0.0.1:4173/landing-pages/atheer/
   kill %1
   ```
   Expected: `200` and a size around `65000` (the lightweight page), not ~9,700,000.

## Maintenance note

Anyone editing the Atheer page must edit `_source/template.html` and re-run
`node landing-pages/atheer/_source/build.js` — both outputs regenerate together. Plan 004
adds a CI drift check that rebuilds and fails on uncommitted differences; if this plan
lands after 004, the workflow needs no change (it diffs the whole `landing-pages/atheer/`
tree). The `qa/ACCEPTANCE-CHECKLIST.md` numbers (Lighthouse 95 mobile) now describe the
*deployed* page, which is the honest state.
